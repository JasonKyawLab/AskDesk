================================================================================
 AskDesk — Self-Hosting Setup Guide
 (for anyone who wants to run their own AI support bot on their own accounts)
 DRAFT — not committed to git yet.
================================================================================

 What you get: a Telegram support bot for YOUR business. It answers questions
 from YOUR FAQs (button menu + AI), hands off to you when it's unsure, and is
 fully brandable — all without editing any code.

 You change only DATA:
   • your FAQs        -> a JSON file you load
   • your shop name / welcome message -> the /edit web page (from your phone)
   • your keys/secrets -> environment variables on your host
 The code is never edited. A bakery, a salon, a shop — same code, different data.


################################################################################
 BEFORE YOU START — collect these
################################################################################

 1. Telegram bot:
      Message @BotFather -> /newbot -> pick a name and a @username ending in
      "bot" -> copy the BOT TOKEN (like 8123...:AAF...).

 2. Your Telegram numeric id (you become the admin):
      Message @myidbot -> /getid -> copy the number (digits only).

 3. Gemini API key (free): https://ai.google.dev -> "Get API key" -> copy it
      (starts with AIza...). Treat it like a password.

 You'll also create free accounts on Supabase (database) and Render (hosting).


################################################################################
 STEP 1 — Database (Supabase, free)
################################################################################

 - Create a project at https://supabase.com (set a database password —
   letters and numbers only, avoid symbols).
 - Database -> Extensions -> enable "vector".
 - Click "Connect" (top bar) -> choose "Session pooler" -> Type: URI -> copy it.
     IMPORTANT: use the Session pooler (port 5432), NOT the transaction pooler
     (6543) and NOT the direct connection (IPv6). Render is IPv4.
 - Replace [YOUR-PASSWORD] with your DB password and add ?sslmode=require.
   This full string is your DATABASE_URL, e.g.:
     postgresql://postgres.xxxx:PASSWORD@aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require


################################################################################
 STEP 2 — Deploy (Render, free)
################################################################################

 - Push/fork the AskDesk repo to your own GitHub (the code is unchanged).
 - Render -> New -> Web Service -> Docker -> pick the repo. Branch: main.
   Region: near you. Instance: Free.
 - Environment variables:
       ASKDESK_DATABASE_URL       = <your Supabase Session-pooler URI>
       ASKDESK_GEMINI_API_KEY     = <your Gemini key>
       ASKDESK_TELEGRAM_BOT_TOKEN = <your bot token>
       ASKDESK_BUSINESS_ID        = 1
       ASKDESK_ENV                = production
   Auto-generated by Render (note the webhook secret's value):
       ASKDESK_TELEGRAM_WEBHOOK_SECRET
       ASKDESK_MAGIC_LINK_SECRET
   Do NOT set ASKDESK_REDIS_URL (empty = all-in-one free mode).
   Do NOT set PORT or ASKDESK_PUBLIC_URL (Render fills these).
 - Deploy. On first boot it connects to Supabase and runs migrations itself.
   Check https://<your-app>.onrender.com/healthz -> {"status":"ok"}.
 - Note your URL and the generated ASKDESK_TELEGRAM_WEBHOOK_SECRET.


################################################################################
 STEP 3 — Register yourself as admin (one time)
################################################################################

 In Supabase -> SQL Editor -> New query -> run (put YOUR telegram id):

   INSERT INTO businesses (id, name, api_key)
     OVERRIDING SYSTEM VALUE VALUES (1, 'Your Shop Name', gen_random_uuid())
     ON CONFLICT (id) DO NOTHING;
   INSERT INTO admins (business_id, channel, external_id, name)
     VALUES (1, 'telegram', 'YOUR_TELEGRAM_ID', 'owner')
     ON CONFLICT DO NOTHING;


################################################################################
 STEP 4 — Connect the bot to your server (one time)
################################################################################

 From a terminal (or run the equivalent curl):

   curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
     --data-urlencode "url=https://<your-app>.onrender.com/webhook/telegram" \
     --data-urlencode "secret_token=<the generated webhook secret>"

 Expect: {"ok":true,...,"description":"Webhook was set"}


################################################################################
 STEP 5 — Load YOUR FAQs
################################################################################

 Write your own faqs.json — an array of {category, question, answer}. The
 CATEGORIES become your button menu automatically (bakery example):

   [
     {"category":"Ordering","question":"How do I place an order?","answer":"..."},
     {"category":"Custom Cakes","question":"Can I order a custom cake?","answer":"..."},
     {"category":"Allergens","question":"Do you have nut-free options?","answer":"..."}
   ]

 Then load them (needs Go + the repo locally, or run from any machine with the
 env vars set):

   export ASKDESK_DATABASE_URL="<your Supabase Session-pooler URI>"
   export ASKDESK_GEMINI_API_KEY="<your Gemini key>"
   export ASKDESK_BUSINESS_ID=1
   make load-faqs file=faqs.json

 To update later: edit faqs.json and re-run with reset:
   make load-faqs file=faqs.json reset=1
 (reset wipes and reloads so the file is the single source of truth.)


################################################################################
 STEP 6 — Brand it (from your phone, no code)
################################################################################

 In Telegram, message your bot: /admin -> ✏️ Edit FAQs -> the web page opens.
 At the top, "Business settings":
     • Shop name        -> e.g. "Sweet Crumbs Bakery"
     • Welcome message  -> use {name} where the shop name should appear
     • Busy / fallback message
     • "Ask a question" prompt
 Save. Changes take effect on the next message — no redeploy.

 You can also add/edit/delete individual FAQs on the same page.


################################################################################
 STEP 7 — Use it
################################################################################

 CUSTOMERS: share your bot link  https://t.me/<yourbotusername>  (on your site,
 receipts, social). They tap Start -> see your menu -> tap a topic for an
 instant answer, or type a question for the AI. Your phone number is never used.

 YOU (admin):
   /admin              -> button panel
     📊 Today's stats
     📥 Pending questions -> tap one -> ✍️ Reply (type your answer; it goes
                            straight to the customer) or 🗑 Dismiss
     ✏️ Edit FAQs         -> the settings + FAQ web page


################################################################################
 KEEP IT AWAKE (optional, free)
################################################################################

 Render free sleeps after 15 min idle (first message after a nap is slow but
 still arrives). To keep it warm: a free cron (cron-job.org) pinging
   https://<your-app>.onrender.com/wake   every 5-10 minutes.


################################################################################
 WEB API (optional) — use AskDesk from your own web app / site
################################################################################

 Besides Telegram, AskDesk exposes a small JSON API so your website or web app
 can show the FAQs and ask questions. Same database, same FAQs — the web app and
 Telegram share everything (edit a FAQ once, both see it).

 Base URL:  https://<your-app>.onrender.com/api/v1
 Auth:      send header  X-API-Key: <your business api key>
            Find your key:  in Supabase SQL Editor ->
              SELECT api_key FROM businesses WHERE id = 1;

 Endpoints:
   GET  /api/v1/config
        -> { business_name, welcome, ask_prompt, categories: [...] }
   GET  /api/v1/faqs
        -> { categories: [ { name, faqs: [ {id, question, answer} ] } ] }
        (an empty knowledge base returns an empty list, NOT an error)
   POST /api/v1/ask     body: { "message": "...", "session_id": "..." }
        -> { answer, answered }        (free text -> AI)

 CORS: set ASKDESK_CORS_ORIGINS to your site (e.g. https://yoursite.com), or "*"
 for any origin. Only needed if a browser calls the API directly.

 --------------------------------------------------------------------------------
 SECURITY — read before exposing the API
 --------------------------------------------------------------------------------
 Safe by design:
   • Read-only. The API cannot add/edit/delete anything (edits stay behind the
     /edit magic link and the loader). No write surface, no SQL injection.
   • Tenant-isolated. A key only ever reads its own business's data — never
     another business's FAQs.
   • Returns only public support content (FAQs + settings). Never keys, tokens,
     conversations, or admin data.

 The real risk is NOT data theft — it's COST/ABUSE of the /ask endpoint:
   • Every /ask call spends your Gemini quota, and there is no rate limiting yet.
     A spammer could drain your daily free quota and break the bot for everyone.
   • If your BROWSER sends the X-API-Key, anyone can read it in dev tools and
     call the API themselves (reading FAQs is harmless; spamming /ask is not).

 Recommended:
   • Call the API from your web app's BACKEND, not the browser, so the API key
     stays server-side (a real secret). Your backend can rate-limit /ask itself.
   • If you must call from the browser: set ASKDESK_CORS_ORIGINS to your exact
     domain (not "*"), and add a rate limit in front of /ask.
   • The GET endpoints (config, faqs) are fine to expose either way — public,
     read-only, isolated.


################################################################################
 NOTES
################################################################################

 • One deployment = one business (single bot). To run a second business, deploy
   another copy with its own bot token + Supabase — same code.
 • Free Gemini limits are shared across all your bot's users (~a few messages
   per minute, a few hundred per day). Buttons don't use AI, so most traffic
   is free. When the AI is over its limit, customers get your fallback message
   and the question lands in your Pending list.
 • Secrets (keys, tokens) live ONLY in environment variables — never in the
   code or the FAQ file.
